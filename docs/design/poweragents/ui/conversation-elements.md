# Conversation elements

The interactive pieces the agent shows inside its reply instead of making the person type: choices and small forms
today (generated by the agent, [D23](../DECISIONS.md#d23)), and later a batched approval, a browser handoff, a time
picker, a card. They are designed as one language, so a new element is assembled from the parts below rather than drawn
from scratch. Whatever produces an element, generated UI or a built-in one, it follows this document.

In `poweragents.pen`: the `Conversation elements` row of `Atoms` and `Organisms` and the column of `Molecules`, and
screens 67–74 (the design log is [history/conversation-elements.md](../history/conversation-elements.md)).

## Where an element sits

- **Inside the agent's reply,** in its body column right of the agent mark, never wider than the text, after the text
  that introduces it. Never a dialog or a pop-up: it is part of what the agent said.
- **At the end of the reply.** The agent asks, shows the element and waits; the conversation's last element is the
  one waiting for the person.
- **Typing always works too.** The composer stays open beside any element ("Albo odpowiedz własnymi słowami…"), and a
  typed message answers the element just as a click would.

## Anatomy

- **Bare or in a card.** A single question with a few fixed answers is a row of buttons bare under the text (screen
  72): it reads as the rest of the agent's sentence. Anything that groups several parts (a form, an approval listing
  several changes, a handoff with a picture) sits in the element card: `surface-soft`, `radius-l`, 16 px padding, white
  controls inside (`organisms/Conversation element`).
- **Choices** are pill buttons. Equal options are all secondary; primary is kept for the answer the agent suggests and
  for a form's send button. One click answers.
- **Fields** have a visible label above them, always. An optional field says so in its label ("(opcjonalnie)");
  required fields carry no mark. Checkbox options are full-width white rows, 40 px high, clickable as a whole.
- **Actions** close a card, left-aligned, primary first (`molecules/Form actions`).

## States

- **Appearing** — while the agent is still writing, the element builds up in place (a form gains its fields, the
  actions come last) and nothing is clickable yet; the writing caret sits inside the card.
- **Active** — the agent has finished and the element is the conversation's last; controls work.
- **Answered** — once the person answers, by the element or by typing, the element stays in the history, inactive: the
  card loses its fill (white with a `border` outline), controls are disabled, text turns `ink-muted`. A picked choice
  keeps a check and its outline (`atoms/Button/Chosen`, screen 74), so scrolling back shows what was picked. The answer
  itself is the person's own message below.
- **Invalid** — a required field left empty shows a message at the field ("Uzupełnij to pole") with an icon in the
  attention colour, and nothing is sent. Checkbox rows in error take the softer `attention-border` outline, so several
  rows do not shout.

## What an answer looks like

The answer is sent as the person's message, in their words, so the conversation reads naturally and the agent reads it
as text: a choice sends the text its button carries (written in the person's voice, "Zacznijmy od CV"); a form sends
its button's text, a blank line, then `Label: value` per filled field.

## Copy and accessibility

- Every label and option is in the person's language; the agent writes them for generated elements.
- Contrast AA in all three palettes, also for control outlines (3:1) and disabled-but-readable text; targets at least
  24 px; every field labelled; an error is announced and tied to its field; Enter sends a form.
- No fields for passwords, card numbers or codes, ever.

## Adding an element

1. Draw it in Pen from these parts — card, choices, fields, actions, the four states — in the `Conversation elements`
   row or column, and a screen showing it in a conversation.
2. Add a section here if it brings something the parts above do not cover (an approval's list of changes, a handoff's
   page picture).
3. A generated element also joins the agent's component library (`packages/common/src/generativeUi/`), which
   generates the agent's `generative-ui` skill; a built-in one is a component in `packages/ui` used by the
   conversation directly.
